The story

The cycle that builds the product.

Every product team runs the same loop: build → ship → use → learn. Fifty years of work — programming languages, agile, cloud, and now coding agents — collapsed the left half. The distance from problem to PR is approaching zero.

The right half hasn't moved. Humans still triage Slack, watch replays, read logs, and try to synthesize "what should we build next?" For every issue that survives, hundreds don't.

Sense is the new bottleneck. More than 95% of behavioral data goes unread.

The teams that have mastered this — Anthropic, Meta, Netflix, Stripe — run proprietary systems that sense, prioritize, ship, and learn at machine speed. Stripe's "Minions" merge 1,300+ PRs a week. Ramp's Inspect authors 57% of merged PRs.

PDLC is the cycle, made general. It runs on the modeled product data Amplitude already owns. It surfaces what matters. It writes the spec. It hands off to your coding agents. It tracks the outcome. Every cycle that closes makes the next one smarter.

descriptionSpec

The artifact every agent inherits.

A planning agent (we call it Wave internally) drafts a structured spec for every opportunity that clears the bar. Problem, evidence, proposed solution, acceptance criteria, target repo, complexity tag.

The spec is the contract between the loop and whichever agent picks up the work. Cursor, Claude Code, a Codex session, a human — they all load the same artifact, with the same backlinks, in the same shape.

boltAct

The spec routes itself.

Based on the complexity tag, the spec opens a branch and dispatches to the right executor. Small, self-contained fixes go to a Cursor cloud agent. Richer-context sessions go to Claude Code. Larger work routes to a human-owned session.

There's no Linear ticket. No Slack handoff. The agent loads the spec via MCP and starts from full context — citations and all.

The review agent goes first.

Before a human ever opens the PR, a separate review agent loads the original spec, runs the modified code in a sandbox, captures a session replay of the change in action, and posts a structured review back to the PR.

Most coding-agent failures aren't "the code doesn't compile" — they're "the agent confidently shipped the wrong thing." The reviewer catches those before humans burn time on them.

Still being built

Citation quality on noisy signals.

Replay analysis is noisy. Some chart and feedback citations go stale. Today, evidence is solid enough to triage from but not always to ship from without re-verification. The quality judge is the main gate; an override taxonomy feeds back as training data.

Gate · 8-failure-mode override taxonomy → labeled retraining

Codebase & environment resolution.

Identifying the right repo, recreating a working dev environment, and confirming whether a bug is still live or already shipped are real time sinks. "Feature already shipped" remains one of our most common override reasons.

Lever · per-area codebase indexing · "what's live" context channel in every spec

End-to-end ship rate on legacy code.

Even with the right repo and a reasonable rec, shipping into a mature codebase still needs heavy review and domain knowledge to sign off. The reviewer agent is the lever we're pulling here — and the lever we expect to keep pulling for a while.
